# ВышКат

Консольное учебное приложение для учета парка кикшеринга. Транспорт принимается на баланс после техосмотра. В инвентаре хранятся транспорт и вещи; отчеты показывают количество транспорта по видам, суммарный расход энергии за сутки и транспорт для новичков (оценка не ниже 6).

Проект реализовал студент БПИ256, Тюрин Илья

## Запуск

Нужен .NET SDK 10. Из папки `project-sharp`:

```powershell
dotnet build Vyshkat.slnx
dotnet run --project src/Vyshkat.Cli
```

В приложении уже есть несколько демонстрационных объектов. Данные хранятся в памяти и исчезают после выхода.

## Использование программы

После запуска выберите номер действия в меню. Чтобы добавить транспорт, используйте пункты `1`-`3` и введите инвентарный номер, оценку удобства для новичка от 1 до 10 и, для электрического транспорта, расход энергии за сутки в кВт·ч. Например, для нового самоката можно указать `TR-SC-002`, оценку `8` и расход `1.5` 

Техосмотр проверяет, что номер транспорта содержит хотя бы 3 символа. Номер должен быть свободен среди всего инвентаря, включая демонстрационные объекты; регистр букв при проверке совпадений не учитывается. При успешной проверке транспорт попадает на баланс. Оценка `6` и выше включает его в список для новичков, но сама по себе не влияет на приемку. Расход энергии не может быть отрицательным.

Пункты `4` и `5` добавляют шлем или зарядную станцию: для них техосмотр не проводится, но номер тоже должен быть уникальным и содержать не менее 3 символов. Пункт `6` показывает весь инвентарь, `7` — количество транспорта и суточный расход энергии, `8` — транспорт для новичков. Для выхода выберите `0`.

## Структура

| Проект | Назначение |
| --- | --- |
| `src/Vyshkat.Core` | Модели транспорта и вещей, техосмотр, правило для новичков, учет парка |
| `src/Vyshkat.Cli` | Консольное меню и точка входа с регистрацией зависимостей |

`Vyshkat.Core` не зависит от консольного приложения или контейнера зависимостей. `FleetService` получает `IServiceCenter` через конструктор. В `Program.cs` стандартный контейнер `Microsoft.Extensions.DependencyInjection` создает настоящий `ServiceCenter`, `FleetService` и `ConsoleApp`. В тестах вместо техосмотра передается простой `FakeServiceCenter`.

## Архитектура и SOLID

- `IInventoryItem` описывает объект на балансе; `IEnergyConsumer` добавляется только объектам, которые расходуют энергию.
- `Transport` и `Thing` содержат общие свойства; конкретные виды представлены отдельными классами.
- `FleetService` отвечает за приемку, инвентарь и отчеты. `ConsoleApp` отвечает только за взаимодействие с пользователем.
- Правило отбора для новичков вынесено в `BeginnerPolicy` с порогом 6.
- Зависимость от `IServiceCenter` позволяет подменить техосмотр в тестах. Новые виды транспорта участвуют в общих отчетах через базовый класс и интерфейс энергопотребления.

## Как расширять

Новый вид транспорта наследуется от `Transport`. Если он расходует энергию, реализует `IEnergyConsumer`. Для интерактивного добавления нужно добавить пункт в `ConsoleApp`. Для склада запчастей можно добавить новые виды `Thing`, а отдельный сервис склада вводить при появлении операций прихода и списания.
